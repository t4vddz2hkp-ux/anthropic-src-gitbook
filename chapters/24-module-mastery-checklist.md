# 第 24 章 模块通关清单与自学检查表

## 本章在第六阶段中的位置

这一章属于第六阶段，也就是把“我感觉自己看懂了”变成“我可以明确检查自己到底掌握到什么程度”的阶段。

## 本章的作用

前面的章节已经把系统讲开了，但学生常见的问题是：读完之后不知道自己到底有没有掌握。本章的任务，就是把“掌握”变成可以检查的标准。

本章不是简单的复习提纲，而是一份模块通关表。你可以把它理解为：

- 阅读任务清单
- 重点文件地图
- 关键概念检查表
- 口头讲解的提问脚本
- 最小合格标准

如果你能逐项完成本章内容，那么你对该系统的理解就不再停留在“看过”，而会进入“能解释、能追踪、能定位、能改造”的层次。

## 使用方法

每个模块都从五个角度检查：

1. 我是否知道它解决什么问题？
2. 我是否知道它最关键的文件？
3. 我是否知道它的核心数据结构？
4. 我是否知道它与其它模块如何交互？
5. 我是否能够复述它的运行流程？

只要有一项回答含糊，这个模块就还没有真正通关。

## 模块一：程序入口与初始化

### 必读文件

- `main.tsx`
- `entrypoints/init.ts`
- `setup.ts`

### 必须掌握的内容

1. 程序是如何启动的。
2. 初始化阶段到底做了哪些准备工作。
3. REPL 界面是在什么时候被接起来的。
4. 为什么入口层不能承担全部业务逻辑。

### 核心检查题

1. `main.tsx` 的职责为什么不是“干所有事”？
2. `init.ts` 与 `setup.ts` 的关系是什么？
3. 初始化链路结束之后，控制权是怎样交给交互层的？

### 通关标准

你能画出“入口 -> 初始化 -> 会话准备 -> REPL”的最小链路图。

- `utils/processUserInput/processUserInput.ts`

- `utils/messages.ts`

### 通关标准

1. 上接输入层。
2. 下接 API 层。

### 核心检查题

1. 模型回复里出现工具调用时，主循环会发生什么变化？
2. 为什么说查询主循环是系统的“调度心脏”？
3. 如果没有上下文压缩，查询循环可能会遇到什么问题？

### 通关标准

你能把查询循环分成几个阶段，并分别解释每个阶段在做什么。

## 如果你真的想验证自己是否掌握

请尝试完成下面五个口头挑战：

1. 不看书，讲清一次请求的完整执行过程。
2. 不看书，比较命令系统和工具系统。
3. 不看书，解释为什么任务系统会让整个项目复杂度明显提升。
4. 不看书，解释为什么这套系统要有会话持久化和上下文压缩。
5. 不看书，回答“如果我要接一个新工具，最少需要摸清哪些文件”。

如果这五题你都能流畅回答，你已经从“阅读者”接近“维护者”了。

## 本章小结

真正的掌握不是“我见过这些文件”，而是“我知道它们为什么在这里、怎样一起工作、出了问题该去哪里看”。本章给你的，就是这样一套可落地的检查标准。下一章我们会把这些检查标准进一步落实为实验、作业和毕业考核。
