# 第 22 章 教师扩展讲稿与课堂板书方案

## 22.1 本章怎么用

前面的章节更像教材正文。  
本章则更像教师讲义：我会直接给出一种可拿来上课的表达方式。

你可以把它用于：

- 课堂讲解提纲
- 黑板板书顺序
- 学生提问引导
- 期末复习串讲

## 22.2 一堂 90 分钟课的标准讲法

### 前 10 分钟：先立总问题

开场不要直接讲代码。  
建议先问学生：

1. 这套源码到底想构建一个什么产品？
2. 它为什么会有 `commands`、`tools`、`tasks` 三套体系？
3. 为什么 `src/ink/` 这样一个终端渲染目录会如此庞大？

这样能把学生从“看代码细节”拉到“看系统问题”。

### 第 10 到 25 分钟：讲一条主线

建议优先讲这一条：

> 用户输入 -> processUserInput -> QueryEngine -> query -> API -> 工具 -> 消息回流

这是整套工程最值得先建立的主线。

### 第 25 到 45 分钟：讲两个关键抽象

建议选：

- `Tool`
- `Task`

这两个抽象最能代表工程水平。

### 第 45 到 65 分钟：讲一个重量级具体模块

建议选：

- `BashTool`

因为它把协议、安全、后台化、UI 都揉在了一起，非常适合作为代表案例。

### 第 65 到 80 分钟：讲扩展和治理

建议讲：

- MCP / Plugins
- Permissions / Compact / SessionStorage

这样学生会意识到，平台不是只会跑，还要能长期治理。

### 最后 10 分钟：收束到系统图

结束前重新画一次总图，让学生形成结构记忆。

## 22.3 黑板板书建议

如果你只有一块黑板，建议按这个顺序写：

### 第一列：主链路

```text
用户输入
  -> processUserInput
  -> QueryEngine
  -> query
  -> API
  -> tool_use
  -> 工具执行
  -> tool_result
  -> assistant
```

### 第二列：三大抽象

```text
Command = 用户入口
Tool = 模型能力协议
Task = 异步执行容器
```

### 第三列：横切系统

```text
Permission
Memory
Compact
SessionStorage
MCP / Plugin
```

## 22.4 教师可以直接使用的讲解词

### 讲 `main.tsx` 时

可以这样讲：

> 这个文件像装配车间的总控台。它本身不完成所有业务，但它负责把启动、配置、会话、命令、工具、UI 和远程能力组装到一起。

### 讲 `Tool.ts` 时

可以这样讲：

> 如果没有 Tool 协议，这个项目会退化成一堆零散函数。正是因为有 Tool 协议，模型才真正拥有一套统一的“可调用能力面”。

### 讲 `query.ts` 时

可以这样讲：

> 这不是一个请求函数，而是一台会反复自我推进的状态机。它一边维护消息历史，一边和模型交互，一边调度工具，一边处理压缩与预算。

### 讲 `AgentTool` 时

可以这样讲：

> 它不是在调用另一个函数，而是在派生新的执行主体。它让系统从“单代理”迈向“多代理平台”。

## 22.5 教师最该避免的三种讲法

### 讲法一：按目录挨个念

这样学生会淹没在细节里，却抓不住主线。

### 讲法二：只讲产品功能，不讲抽象

学生会知道“能做什么”，却不知道“为什么这样设计”。

### 讲法三：只讲概念，不回到文件

学生会觉得很抽象，最后落不到具体源码。

最佳方式永远是：

> 系统主线 -> 抽象 -> 具体文件 -> 再回到系统主线

## 22.6 适合课堂提问的 12 个问题

1. 为什么 `main.tsx` 不是所有逻辑都自己做？
2. `REPL.tsx` 和 `QueryEngine.ts` 的边界在哪里？
3. 为什么消息是系统内部的统一语言？
4. 为什么命令和工具必须分开？
5. 为什么工具要自带 UI 渲染方法？
6. 为什么 BashTool 需要后台任务系统配合？
7. 为什么 AgentTool 不等于“递归调用自己”？
8. 为什么 MCP 最终也要汇入工具池？
9. 为什么 transcript 不能记录所有 progress？
10. 为什么自动压缩必须写进 query 主循环？
11. 为什么插件系统需要版本缓存和来源校验？
12. 这套架构最像哪种操作系统或平台结构？

## 22.7 期末串讲建议

如果课程最后只剩 30 分钟复习时间，建议按下列顺序快速串讲：

1. 一条主链路  
   输入 -> Query -> Tool -> Result -> Persist

2. 三个核心抽象  
   Command / Tool / Task

3. 四个横切治理系统  
   Permission / Memory / Compact / SessionStorage

4. 两个代表性重模块  
   BashTool / AgentTool

5. 一个扩展总线  
   MCP / Plugin

## 22.8 本章小结

如果你是一位教师，真正要带给学生的不是“记住多少函数名”，而是：

> 学会把复杂源码收束成主线、抽象、模块、交互和治理五个层次。

一旦学生掌握了这种阅读方式，他们不仅能读懂这个项目，也能迁移到别的大型工程里去。
