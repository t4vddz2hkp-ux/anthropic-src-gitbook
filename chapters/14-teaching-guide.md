# 第 14 章 教学组织建议

## 学习目标

- 把前面 13 章内容转化为可操作的课堂方案
- 给教师提供节奏、重点和互动建议
- 让学生能够从“看懂”过渡到“能讲、能画、能追踪”

## 14.1 推荐课程安排

下面给出一套 6 次课的建议安排，每次 90 分钟：

| 课次 | 主题 | 对应章节 |
| --- | --- | --- |
| 第 1 讲 | 系统定位与架构总览 | 第 1、2 章 |
| 第 2 讲 | 启动链路、REPL 与状态管理 | 第 3、4 章 |
| 第 3 讲 | 输入处理、消息模型与 Query 主循环 | 第 5、6 章 |
| 第 4 讲 | Tool 协议与 BashTool | 第 7、8 章 |
| 第 5 讲 | AgentTool、任务系统、多代理 | 第 9 章 |
| 第 6 讲 | MCP/插件、横切系统、综合复盘 | 第 10、11、12、13 章 |

## 14.2 每次课最应该达成的目标

### 第 1 讲

让学生意识到：

- 这是平台型工程
- 要按系统分层来读
- 不能按“某个页面功能”来理解

### 第 2 讲

让学生说清楚：

- 程序如何启动
- REPL 为什么是 Shell 层
- `AppState` 为什么这么大

### 第 3 讲

让学生能画出：

- 用户输入到消息流的路径
- 一轮 `query()` 的时序图

### 第 4 讲

让学生能解释：

- 为什么 Tool 是统一协议
- 为什么 BashTool 这么复杂却又合理

### 第 5 讲

让学生能区分：

- sync agent
- async agent
- teammate
- remote agent
- worktree isolation

### 第 6 讲

让学生建立：

- 扩展系统观
- 横切治理观
- 综合系统观

## 14.3 最适合的课堂互动方式

### 方式一：画图讲述

要求学生在白板上画：

- 启动链路图
- query 时序图
- AgentTool 决策树

### 方式二：源码定位竞赛

教师出题，学生用 `rg` 找：

- 工具注册中心在哪里
- agent 背景化在哪里发生
- session transcript 在哪里落盘

### 方式三：角色扮演

把学生分成四组：

- “用户输入组”
- “Query 内核组”
- “工具执行组”
- “任务/持久化组”

每组负责解释自己那段链路如何与其它组交互。

## 14.4 建议的考核方式

### 过程考核

- 课堂时序图
- 关键函数口头讲解
- 代码追踪小报告

### 结果考核

可选题目：

1. 完成一份“单轮 query 运行图”
2. 完成一份“BashTool 安全设计分析”
3. 完成一份“AgentTool 与任务系统协作分析”
4. 完成一份“插件/MCP 如何进入主系统”的结构说明

## 14.5 讲授时要反复回收的关键词

建议整门课反复回收这些关键词：

- 装配器
- Shell
- 消息流
- 协议
- 状态机
- 调度
- 任务容器
- 扩展总线
- 横切治理

这些词会帮助学生形成稳定的系统语言。

## 14.6 最后给教师的建议

讲这套代码时，最怕两件事：

1. 被海量文件牵着走
2. 被产品细节淹没掉架构主线

所以最有效的讲法永远是：

- 先讲系统主线
- 再讲关键抽象
- 再讲代表性模块
- 最后讲特殊分支和高级机制

## 本章小结

这本教材最适合的使用方式，不是一次性讲完，而是围绕三条主线反复展开：

- 用户输入主线
- Query 执行主线
- Tool/Task/Agent 扩展主线

只要学生能反复把这三条主线讲清楚，他们就已经真正理解了这套源码。
